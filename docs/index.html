DroneBench is a test bench for small electric fixed-wing aircraft. It analyses a design, runs 16 pass or fail checks, and scores it. An agent edits the design with a command, and each edit is kept or rejected with the reason.

What the agent tried

One Claude Code run, 12 attempts allowed, 11 used. It read a report of which parts were dead weight, removed them one at a time, and tried new propellers twice. DroneBench rejected both propeller swaps because the score went down.

What it will not allow

Deleting the wiring. The harness check needs a minimum wire mass for the speed controllers, servos and flight controller.

Deleting the rudder. The control check needs a surface for roll, pitch and yaw.

Deleting a motor mount. Every part must stay attached to one airframe, so a motor left floating fails.

Inventing a 400 Wh/kg battery. Specs an agent types in are clamped to what real parts do, and flagged.

Removing real dead weight. This is allowed. Armor plating, a fuselage section and ballast made up 27 of the 38 minutes.

Run it

Python 3.11 or newer. Claude Code is optional, any script can use the same commands.

# install
git clone https://github.com/sisiphamus/dronebench && cd dronebench
uv venv && uv pip install -e .

# make a workspace and open the live dashboard
dronebench init runs/demo --fixture falcon_v2 --steps 12
dronebench serve runs/demo --open

# in a second terminal, let an agent iterate
dronebench run runs/demo --agent claude
dronebench run runs/demo --agent random      # the baseline to beat

# or do what the agent does
dronebench try runs/demo --ops ops.json --note "ballast is dead weight"
dronebench build runs/demo --set wing.span_mm=2200

How far to trust it

The physics is analytic. It uses lift and drag estimates, a motor, propeller and battery model, a cantilever spar and neutral point stability. Expect about 15% error. That is enough to rank designs against each other. It does not show that an aircraft is safe to fly, and the Falcon V2 wing shape is an assumption written down in the repo.
